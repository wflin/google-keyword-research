# 产品需求文档（PRD）

## 1. 产品定位

Google Keyword Research 是一个供个人使用的海外需求发现工具。它的目的不是成为一个对外销售的关键词工具，而是帮助项目所有者在开发海外 AI/SaaS/工具产品之前，用数据快速判断“有没有人搜、需求是否增长、用户是否有商业意图、这个方向是否值得继续研究”。

核心闭环：

> 想法/关键词 → Google 搜索需求 → 关键词扩展 → 趋势与商业指标 → 机会筛选 → 人工进一步验证 → 决定是否开发产品

## 2. 背景与问题

用户希望采用“先发现海外需求，再开发产品”的创业方式。当前最大问题不是开发能力，而是如何低成本、快速、持续地发现真实需求。

Google 搜索是验证海外需求的重要信号。Google Keyword Planner 可以提供月均搜索量、历史月度搜索量、竞争度、竞争指数及出价等数据。因此需要建立一个自己的研究工具，避免每次打开 Google Ads 页面手工查询、复制和整理。

## 3. 产品目标

### 3.1 第一目标

把 Google Keyword Planner 的关键词研究流程变成一个简单、可重复、可保存的个人工作台。

### 3.2 第二目标

让一个产品想法可以快速扩展为一组相关关键词，并进行横向比较。

### 3.3 后续目标

在稳定获得 Google 数据后，增加 AI 分析能力，让系统辅助回答：

- 这个关键词代表什么需求？
- 用户为什么搜索？
- 是否存在明确的产品形态？
- 商业意图高不高？
- 竞争是否过于激烈？
- 是否适合个人开发？
- 是否值得进一步做竞品和用户验证？

## 4. 非目标

第一版明确不做：

- 不做公开注册的 SaaS 平台
- 不做收费系统
- 不做广告投放平台
- 不代替 Google Ads 投放
- 不通过爬虫伪造或推算 Google 搜索量
- 不承诺“预测某个产品一定成功”
- 不在第一版接入大量第三方 SEO 数据源

## 5. 目标用户

唯一目标用户：项目所有者本人。

因此产品设计优先考虑个人研究效率，而不是多人协作、权限、审计、计费等企业需求。

## 6. MVP 功能

### 6.1 单个/批量关键词查询

用户输入一个或多个关键词，系统查询 Google Ads Keyword Planning API。

支持：

- 单关键词
- 多关键词批量输入
- 文本粘贴导入
- 去重
- 查询结果保存

### 6.2 地区与语言

用户可以选择：

- 国家/地区
- 语言

第一版至少支持美国 + English，并保留后续扩展其他国家和语言的结构。

### 6.3 Google 历史关键词指标

第一版至少展示：

- Keyword
- Average monthly searches
- Monthly searches / 历史月度搜索量（API 可提供时）
- Competition
- Competition index（API 可提供时）
- Low top-of-page bid
- High top-of-page bid
- 数据时间范围

所有 Google 数据必须明确标注数据来源和查询时间。

### 6.4 趋势展示

将历史月度搜索量以简单折线图展示，使用户快速判断：

- 上升
- 下降
- 稳定
- 季节性

第一版不要求复杂预测模型。

### 6.5 关键词扩展

输入一个种子关键词后，允许调用 Google Keyword Planner 获取相关关键词建议。

用户可以把建议关键词加入研究列表，再统一查询和比较。

### 6.6 筛选与排序

支持按以下字段筛选/排序：

- 搜索量
- 趋势
- 竞争度
- CPC
- 关键词文本

后续可增加机会评分排序。

### 6.7 研究记录

每次研究应保存：

- 研究主题
- 种子关键词
- 国家
- 语言
- 查询时间
- 关键词结果
- 用户备注

用户可以回看以前研究过的方向，避免重复查询。

## 7. AI 产品机会分析（第二阶段）

AI 分析必须建立在真实采集的数据之上，不能把模型猜测当成 Google 数据。

AI 输出建议包括：

- 需求解释
- 用户可能是谁
- 搜索意图
- 商业意图
- 可能的产品形态
- 可能的收费方式
- 竞争风险
- 个人开发难度
- 机会评分（0-100）
- 推荐结论

机会评分仅作为研究辅助，不作为投资或商业成功保证。

## 8. 未来的完整需求发现流程

未来可以逐步扩展为：

> 种子想法 → Google 关键词 → 相关关键词树 → 搜索趋势 → 商业意图 → SERP/竞品 → Reddit/社区用户痛点 → 产品形态 → MVP → 收费模式 → 开发优先级

其中 Google Keyword Research 是整个流程的第一层数据基础设施。

## 9. 核心用户流程

### 流程 A：验证一个想法

1. 输入种子关键词
2. 选择国家和语言
3. 查询
4. 查看搜索量、趋势、竞争度和 CPC
5. 查看相关关键词
6. 将高价值关键词加入研究列表
7. 记录备注
8. 决定是否继续做竞品/用户研究

### 流程 B：批量寻找机会

1. 准备一批关键词
2. 批量查询
3. 按搜索量/趋势/CPC/竞争度排序
4. 找出异常高增长或高商业意图词
5. 进入单个关键词详情
6. 进一步验证产品机会

## 10. 数据原则

- Google 数据必须来自 Google Ads API 的合法接口。
- 不依赖网页 DOM 抓取 Keyword Planner。
- 不硬编码搜索量。
- 对 API 数据进行缓存，减少重复请求。
- 保存数据来源、查询时间和国家/语言等上下文。
- API 失败时必须明确提示，不能返回看起来真实的假数据。

## 11. 成功标准

MVP 完成后，用户应能在几分钟内完成一次完整的关键词需求验证：

> 输入想法 → 获得真实 Google 数据 → 扩展关键词 → 查看趋势 → 筛选高潜关键词 → 保存研究结果。

如果这个流程可以稳定运行，就认为第一阶段成功，不以页面复杂度或代码量作为成功标准。
